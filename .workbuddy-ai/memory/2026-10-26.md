# 2026-10-26

## 修复：中文输入时混出英文候选（Chrome / CleanShot X）

现象：小狼毫（Rime）中文状态候选栏混入英文词。定位到两个来源：
1. `easy_en` 英文码表（`table_translator@english`）——整本英文词典被塞进候选。
2. `dicts/custom_phrase.txt` 里手工加的英文短码条目（`ch`→Chrome、`cs`→CleanShot X、`gh`→GitHub），
   这些 1–3 字母短码与小鹤双拼编码大量撞车（ch=chang、cs=cong、gh=gang）。

改动：
- 新增 `lua/no_english.lua`（`no_english_filter`），丢弃「纯 ASCII 字母」候选；
  含汉字/符号/emoji 的候选（B站、U盘、㎡、🐂️🍺️）和纯符号（> ≥）保留。字节级判断，不依赖 utf8 库。
- `rime.lua` 注册 `no_english_filter = require("no_english")`。
- 三个方案过滤器链加入 `lua_filter@no_english_filter`：
  `flypy_bt.schema.yaml`、`double_pinyin_flypy.custom.yaml`、`luna_pinyin_simp.custom.yaml`。
- 停用 easy_en：`flypy_bt.schema.yaml` 删 translators/`english:`/dependencies 条目；
  `double_pinyin_flypy.custom.yaml`、`luna_pinyin.custom.yaml` 注释掉（保留恢复说明）。
- 两个 `custom_phrase.txt`（根目录 + `dicts/`）表头加说明；英文条目本身保留未删。

部署：`python -c "import manage_words as m; m.deploy()"`（走 librime C API，比 WeaselDeployer /deploy 可靠）。
验证：日志中不再加载 `easy_en`；无 lua 报错。

已知遗留（与本次无关）：`charset_filter@gb2312` 参数不被支持（每次按键刷 ERROR），
`opencc/emoji.json`、`symbol.json` 在部署器进程里报 not found。

备份：`backup-english-fix/`（改动前的 7 个文件）。
